Every system deserves a butler.

Barnaby is a voice-first butler for any codebase. Point him at a repo and Synapse makes it agent-ready in seconds. When he can't do what you ask, he grows: he unlocks endpoints the code already has, composes your habits into skills, and builds the endpoint nobody ever wrote.

How central Synapse is

Synapse isn't the setup step. It's the engine.

Judges score how central Synapse is. In Barnaby, every growth moment is a Synapse command. Even the departing expert's README matters: --smart-names reads it, so Theo's notes become Barnaby's understanding of the system.

  1. 1

    Connect

    Scan any repo; expose the read-only tools first.

    synapse build --auto --local --endpoints "GET /jobs/open,…"
  2. 2

    Unlock

    Expose an endpoint Synapse already discovered, on request, after one click.

    synapse build --auto --local --endpoints "…,POST /purchase-orders"
  3. 3

    Compose

    Fuse a repeated chain of calls into one skill, verified by replaying it.

    synapse build --custom --local -q "hand back a finished bike"
  4. 4

    Build

    Nobody else does this

    Barnaby writes the missing endpoint; you approve the diff; Synapse rescans and serves it.

    synapse build --discover

Built against the rubric

Four criteria, four answers

The guide lists exactly how Track 4 is judged. Each criterion has a concrete answer in the plan, not a hope.

Criterion 1

Originality and real-world value

  • Voice-first operation of systems nobody wants to rewrite.
  • One product, four real needs: greasy hands, a departing expert, a new hire, an enterprise estate.
  • Growth tiers nobody else reaches (Build).

Criterion 2

How central Synapse is

  • Four Synapse modes in one demo: Auto, Custom, --discover, --smart-names.
  • Remove Synapse and Barnaby can't connect, unlock, compose or grow.
  • Works on any repo Synapse can scan, shown on several in the montage.

Criterion 3

Technical execution

  • Maintained libraries where it counts: Pydantic AI, Pipecat, Claude Agent SDK, MCP.
  • Code changes in a git worktree, gated by your eyes and by tests.
  • 18 Synapse pitfalls designed around before line one, confirmed in a smoke test.

Criterion 4

Quality of the demo

  • A cinematic film rendered from code, as with Quorum.
  • A real walkthrough you record, which I edit.
  • A "for judges" table and an honest real-vs-mocked list in the README.

Bring your own model

AnthropicOpenAIGeminiGroqOpenRouterBedrockVertexOllama · local, free

Our runs: heavy thinking and code writing on your local Claude Code, at no extra cost. The Claude API is only for the split-second front desk and for recording. The Build tier's code writer is Claude-only.

Hand-rolled, on purpose

  • sherpa listening adapter, ~100 lines (no integration exists)
  • wake-word gate, ~40 lines
  • the glue between layers

Delete the folder, nothing remains

Every venv, cache, model and config lives in the repo. Your ~/.claude settings and plugins never leak into the code writer.

De-risked

We already know where Synapse bites

Synapse 0.1.9 pitfalls mapped to design rules

18

Another team published a dozen with reproductions; reading Synapse's own source found more.

See all 18, each with the rule it becomes
  • Local Auto mode drops query parametersPath params and JSON bodies only
  • Router and blueprint prefixes are droppedFull paths in every decorator, including code Barnaby writes
  • POST bodies only work if the model is in the route's fileModels live beside their routes
  • No auth headers are ever sentThe shop app runs without login (local, single shop), disclosed
  • Literal body fields are dropped (confirmed)Plain str with validation in the handler
  • Every tool parameter is typed Any, none required (found in smoke test)Fix-up step restores types and required flags
  • Generated servers need mcp==1.30A separate, pinned venv for generated servers
  • raise_for_status hides API error bodiesDisclosed fix-up step on generated servers
  • Repeated local builds write _2.py, _3.pyThe driver renames output after every build
  • Local Auto asks for a model key it doesn't useSet the provider for the run
  • Custom mode scans its own earlier outputsPark outputs before each Compose build
  • Custom code generation invents undocumented keysDocstrings document every returned dict
  • Empty route paths are skippedNever use "" as a path
  • Flask <int:id> params are pasted literallyFastAPI {id} style only
  • Language = most source files among languages with a root marker fileKeep Python dominant in scanned dirs
  • Routes must appear in a file's first 64 KBSmall route files
  • Hosted Express/TypeScript builds are brokenOnly Python systems in the hero demo
  • Writes ~/.synapse even with telemetry off (confirmed)Synapse runs with its home redirected into the repo (verified)
